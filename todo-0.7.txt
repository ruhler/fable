Fble 0.7 TODO
=============
Things to consider doing for the fble-0.7 release.

* Make programs run twice as fast.
 - Use native stack for stack allocations.
 - Arrange for tail call args to end up at their final destination
   Rather than have to be copied via tail call arg?
 - Return stack allocated value directly instead of gc reallocating if it
   lives on caller's stack frame?
 - Inline FbleCall into aarch64 backend.
 - Specialize call logic based on what we can figure out statically in terms
   of number of args expected and tail/non-tail possibilities.
 - Avoid redundant undef checks on values based on static info.
 - Use a special ref value instead of NULL to represent undefined values?
 - Something to reduce overhead associated with streams.
   See thoughts/fble-0.6/stdlib.map.txt for analysis and discussion.
   See thoughts/fble-0.6/stdlib.stream.txt for performance costs of Stream@.
   For example, changing Data@<Int@> and Data@<IntP@> to use Put/End instead
   of s/put/return.

* Reimplement fbld in rust?

* Figure out a way to test foreign function not found
 - Interpreted gives runtime error.
 - Compiled gives link time error not an any particular line number.
 - We would need some extra spec infra support to describe this.
 - Add spec test for Foreign value not found in interpreted case.

* Switch to sdl3?
* Standardize /App%
 - Add dpi as separate from width and height?
 - Add a vsync event instead of timer tick event?
 - Add support for hitting X button on Snake game in windows?
* Standardize /Network%
 - If we support port 0, we need a way to ask what the port used was.
   And add it to the doc comments for creating a server.
 - Consider if we should support reuse addr option, or if we can avoid that.
 - Need a way to return error messages to end user.
 - See thoughts/fble-0.6/networking.txt for more discussion.
* Consider pulling test, rand, io out of std into separate std-* packages.
 - See thoughts/fble-0.6/stdlib.txt for some discussion.

* Improve the performance of fble-pprof.
  Taking more than a minute for a 5MB profile feels way too slow.

* Fix jank in fble-invaders
  See thoughts/fble-0.6/jank.txt

* Figure out a real solution to error handling in general?
 - Examples to consider: file read/write, parsing an int.

* Be able to typecheck body of a let where the variables aren't all well
  typed, to get more error messages at once.

* Optimize C and interpreter backends like we did aarch64?
  By inlining logic to access fble values instead of calling library
  functions.

* Revamp program/module loading
 - see thoughts/fble-0.5/modular_compilation.txt for the design.
 - goal is to allow precompiled modules to depend on interpreted modules,
   validate types as required at link time, and avoid recompiling
   the implementation (rather than just the type) of a module you depend on.
 - see thoughts/fble-0.5/modular_compilation.txt for additional context.
 - clarify the spec with respect to builtins referring to other builtins and
   the recursive module requirements in case of difference between builtins,
   .fble files, and header files.
 - Add tests for:
   a. Try to compile a builtin module.
   b. builtin A -> builtin B, .fble C -> builtin B.
   c. builtin A, A.fble.@ -> B.fble, B.fble -> /C%,
      C.fble has bugs, C.fble.@ doesn't. This should not fail to execute.
 - consider separating the FbleModule* for execution and for type for a given
   module path.
 - Add option for loading modules from .so files?
 - have fble-cli check that the function has the right type?
 - load minimum dependencies needed for type checking when possible?

* Add --typecheck option to fble-compile
 - You pass the path of a module with the same type expected for the module
   being compiled.
 - Use it in fble-cli and fble-app for better type checking.

* Improve standard library documentation
 - Generate docs for stdlib documentation, including a summary page and
   details page of all modules/functions.

* Implement a poker solitaire tutorial for fble
 - With the goal of getting people up and running as fast as possible in fble
   with practical examples, without having to learn all details of the
   language first.

* Update all the sample apps for latest features, styles, idioms.

* Increase standard library test coverage.
* Implement more rosettacode.org tasks.

* Design a package management / versioning scheme?
 - see thoughts/fble-0.5/modular_compilation.txt for context.

* Fix potential GC gen overflow?
 - See thoughts/fble-0.3/stack_alloc.txt for details.
 - See thoughts/fble-0.5/gc.txt for more thoughts.

* New apps
 - IEEE floating point support.
 - More benchmark games.
 - Implement an image viewer.
 - bitcoin miner
 - gzip, gunzip.

* Fble Language Features
 - Add support for mutable data structures?
 - Add some way to catch or recover from errors at runtime?
   Vital for composition.
   See thoughts/fble-0.6/stdlib.test.txt, thoughts/fble-0.6/exceptions.txt,
   thoughts/fble-0.6/stdlib.stdio.txt for discussion.
 - Some way to implement a web server that can handle multiple requests
   concurrently?
 - Think seriously about compatibility as the language and libraries evolve.
 - Review literals again, because they still don't feel quite right.

* Fbld Language
 - modularity
 - Better support for structs in fbld language, so its easier to write decent
   performing fbld code.
 - Have an 'if' primitive instead of 'ifeq' and 'ifneq'?
 - The @plain builtin is really strange. I had trouble coming up with a test
   case for it. Consider if there's some way we can get rid of that or make it
   more sensible.
 - Clarify in spec if @if[a@x][b@x] ... is an error or not.
   Or redesign semantics of fbld to avoid that question entirely.

* Fbld C implementation
 - Change FbldMarkup type to more explicitly distinguish between the different
   kinds of markups.
 - Figure out how to associate a location with empty markup.
 - Avoid constructing markups with singleton sequences?

* Implement a custom debugger for fble
 - That works on all backends.
 - That supports single step through code.
 - That supports field access.

* Implement deflate algorithm.
 - Switch to gzip format for pprof files.
 - Update fble-pprof to support compressed profiles.
 - Can use uncompressed blocks to start for --profile and fble-pprof.
