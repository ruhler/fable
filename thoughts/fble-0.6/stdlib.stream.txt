Stream and ForEach APIs are close. I'm pretty sure the stream API gives us the
potential to break out early but ForEach does not. Consider:

  <@ A@>(List@<A@>)<@ B@>(B@, (A@, B@) { B@; }) { B@; }
  ForEach = <@ A@>(List@<A@> list)<@ B@>(B@ base, (A@, B@) { B@; } body) {
    list.?(empty: base);
    ForEach(list.items.tail, body(list.items.head, base), body);
  };

  <@ A@>(List@<A@>) { Stream@<A@>; }
  Puts = <@ A@>(List@<A@> values) {
    values.?(empty: Return<A@>);
    Unit@ _ := Do(Put(values.items.head));
    Puts(values.items.tail);
  };

In ForEach, we traverse the entire list regardless. The body itself might just
be a thunk. In Puts, assuming Do was actually lazy, the recursive call could
be lazy. I should do it properly and write it out directly:

  <@ A@>(List@<A@>) { Stream@<A@>; }
  Puts = <@ A@>(List@<A@> values) {
    <@ S@>(S@ return, (A@, S@) { S@; } put) {
      values.?(empty: return);
      put(values.items.head, Puts(value.items.tail, return, put));
    };
  };

Written this way, we could just a value for S@ that makes it a thunk so that
the tail call to Puts doesn't actually evaluate until you choose to.

Notice that Stream effectively builds from back to front. ForEach builds from

How about a For function? The goal is to be able to break out early.

  For@ = <@ A@> { +(A@ continue, A@ break); };
  <@ A@>(Stream@<A@>)<@ B@>(B@, (A@, B@) { For@<B@>; }) { B@; }
  For = <@ A@>(Stream@<A@> stream)<@ B@>(B@ base, (A@, B@) { For@<B@>; } body) { B@; }
    S@ = (B@) { B@; };
    S@ return = (B@ b) { b; };
    put = (A@ x, S@ f, B@ b) {
      For@<B@> fb = body(x, b);
      fb.?(continue: f(fb.continue));
      fb.break;
    };
    stream(return, put, base);
  };

Notice we don't call f unless the result was 'continue' instead of break.

I claim the Stream@ approach is better than the Iter@ approach only because it
passes the partial thunk down to a callee rather than back up to the caller.
Going down to the callee means the thunk can live on the stack. If we go back
up to the caller, we might have to GcAlloc.
